# 22_树莓派5系统镜像官方依据

> 任务范围：只依据 Raspberry Pi 官方 docs/下载站/pi-gen、Debian 官方资料、Hugging Face LeRobot v0.6.0 官方文档/源码/PyPI。
>
> 统一访问日期：2026-07-29（按任务要求记录）。

## 结论摘要

对“Raspberry Pi 5 8GB + 64GB SD + Raspberry Pi OS Lite 64-bit Trixie + LeRobot v0.6.0”的官方依据核对结果如下：**OS 选型、Debian Trixie / Python 3.13、Pi 5 供电散热、CSI 相机、GPIO/串口、headless 首启、systemd 硬化、LeRobot 0.6.0 commit 绑定、torch 2.7.1 与 torchvision 0.22.1 的 arm64/cp313 wheel**均可在一手资料中找到直接或间接依据。**“OpenCV 4.13”无官方 PyPI 发布依据；SO-101/SR-ARM101 去夹爪五轴、电磁铁 GPIO/MOSFET 具体接线、顶置 UVC 具体型号兼容性**在限定来源内仍属 **UNKNOWN/需实机验证**。

### 4. Headless：用户、SSH、网络

1. **Headless 首启可由 Raspberry Pi Imager 官方预配置用户名、SSH、网络**。Raspberry Pi 官方 getting started 文档明确支持通过 Imager 在写盘前配置 hostname、用户、SSH、网络。  
   官方 URL：<https://www.raspberrypi.com/documentation/computers/getting-started.html>  
   官方 URL：<https://www.raspberrypi.com/software/>  
   访问日期：2026-07-29

2. **传统 headless 回退法仍有官方依据：`ssh` + `userconf.txt`**。官方文档说明若未通过 Imager 预配置，可在 bootfs 放置空文件 `ssh` 并用 `userconf.txt` 写入 `username:encrypted-password`；密码哈希可用 `openssl passwd -6`。  
    官方 URL：<https://www.raspberrypi.com/documentation/computers/getting-started.html>  
    访问日期：2026-07-29

3. **NetworkManager 是 Raspberry Pi OS Bookworm 以来的默认网络栈，Trixie 沿用该方向；同时 Trixie 新增 cloud-init / Netplan 首启路径**。官方新闻说明 2025-11-24 之后的 Trixie 镜像引入 cloud-init，boot 分区包含 `user-data` / `network-config` / `meta-data`，并逐步替代旧 `firstrun.sh` 定制流程；旧 `ssh` + `userconf.txt` 仍可用。  
    官方 URL：<https://www.raspberrypi.com/news/cloud-init-on-raspberry-pi-os/>  
    官方 URL：<https://www.raspberrypi.com/documentation/computers/getting-started.html>  
    官方 URL：<https://www.raspberrypi.com/documentation/computers/os.html>  
    访问日期：2026-07-29

4. **镜像侧建议：优先采用 Imager / cloud-init 预置用户、SSH、公钥和网络，不再依赖旧式 `wpa_supplicant.conf` boot hack**。在限定官方来源内，Trixie 的方向是 cloud-init + Netplan + NetworkManager；旧方法仅作 fallback。  
    官方 URL：<https://www.raspberrypi.com/news/cloud-init-on-raspberry-pi-os/>  
    官方 URL：<https://www.raspberrypi.com/documentation/computers/getting-started.html>  
    访问日期：2026-07-29

### 6. systemd 与安全硬化

 1. **Debian trixie 官方 manpage 为 systemd 服务硬化提供直接依据**。可用硬化项包括 `NoNewPrivileges=`, `ProtectSystem=`, `ProtectHome=`, `PrivateTmp=`, `CapabilityBoundingSet=`, `SystemCallFilter=`, `DynamicUser=`。对上位机服务，这些选项可作为默认模板。  
    官方 URL：<https://manpages.debian.org/trixie/systemd/systemd.exec.5.en.html>  
    官方 URL：<https://manpages.debian.org/trixie/systemd/systemd.service.5.en.html>  
    访问日期：2026-07-29

 2. **推荐的镜像安全基线（有官方 manpage 依据）**：
    - `NoNewPrivileges=yes`
    - `ProtectSystem=strict`
    - `ProtectHome=yes` 或 `read-only`
    - `PrivateTmp=yes`
    - 最小化 `CapabilityBoundingSet=`
    - 若程序支持，再考虑 `DynamicUser=yes` / `Type=notify`

    但这些是**可由官方机制支撑的工程建议**，并非针对本项目的现成官方 unit 文件。GPIO、串口、相机、日志写目录会影响最终 hardening 取值，故仍需联调验证。  
    官方 URL：<https://manpages.debian.org/trixie/systemd/systemd.exec.5.en.html>  
    官方 URL：<https://manpages.debian.org/trixie/systemd/systemd.service.5.en.html>  
    访问日期：2026-07-29

## 建议落地口径

1. **镜像基线可写为**：Raspberry Pi 5 8GB / Raspberry Pi OS Lite 64-bit (Debian 13 Trixie) / arm64 / Python 3.13。
2. **首启策略可写为**：优先 Raspberry Pi Imager 预置用户、SSH、公钥、网络；Trixie 新镜像优先 cloud-init；保留 `ssh` + `userconf.txt` 回退路径。
3. **依赖基线可写为**：LeRobot 0.6.0（commit `30da8e687a6dfc617fcd94afc367ac7071c376ce`）、torch 2.7.1、torchvision 0.22.1；**不要把 OpenCV 4.13 写成已获官方依据**。
4. **安全基线可写为**：systemd 服务默认启用 `NoNewPrivileges=yes`、`ProtectSystem=strict`、`PrivateTmp=yes` 等，再按 GPIO/串口/相机访问需求放宽。
5. **硬件表述需保守**：SO-101/SR-ARM101 去夹爪五轴、电磁铁驱动级、UVC 型号兼容性必须标记为 **UNKNOWN/待实机验证**，不得写成官方已确认。

## UNKNOWN 与实机验证清单

1. **SO-101 / SR-ARM101 去夹爪五轴**：限定来源内未形成完整官方机械配置证据链，需结合实物 BOM、舵机拓扑、项目侧数据契约确认。
2. **电磁铁 GPIO/MOSFET 驱动电路**：需按实际电磁铁电流、电压、续流设计、EMI、共地与回扫情况做台架验证。
3. **顶置 UVC 摄像头具体型号**：需验证枚举、供电、分辨率/FPS、V4L2 节点、长时间稳定性。
4. **Feetech 相关依赖在 arm64/Python 3.13 的完整离线闭包**：需先生成 wheelhouse 再在断网 Pi 5 上 cold install。
5. **OpenCV 替代版本**：既然 4.13 未证实，应改成“以官方已发布版本为准”，并在目标平台做 import/摄像头/编解码验证。
6. **64GB SD 实际 endurance 与写放大**：官方来源能证明可用 microSD，但无法替代特定卡型号的寿命/性能实测。

## 残余风险

1. **高风险**：文档目标若仍写“OpenCV 4.13”，会与官方可证发布状态冲突。
2. **中风险**：Trixie 的 cloud-init/Netplan 与旧 `userconf.txt` 流程并存，自动化脚本若混用可能导致首启配置漂移。
3. **中风险**：Pi 5 若使用非 27W 官方供电，UVC 摄像头/USB 外设/风扇并挂时可能触发欠压或 USB 电流限制。
4. **中风险**：systemd `ProtectSystem=strict` / `DynamicUser=` 可能影响 GPIO、串口、相机设备访问与日志落盘，需要逐项放行。
5. **中风险**：LeRobot 0.6.0 虽支持 Python >=3.12，但完整依赖闭包在 arm64/cp313 上仍需用最终 wheelhouse 做一次断网冷安装验证。
6. **中风险**：电磁铁驱动级、电源回扫、地线噪声未在限定来源内得到现成官方方案，必须台架验证后再固化到镜像默认服务。
