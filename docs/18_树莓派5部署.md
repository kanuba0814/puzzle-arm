# 18 树莓派 5 部署

## 系统原则

- 使用 64 位 Raspberry Pi OS 或已验证的 64 位 Linux。
- LeRobot 固定 v0.6.0；该版本官方说明最低 PyTorch 为 2.7。
- 训练依赖与推理依赖分离，Pi 不安装不需要的训练组件。
- 使用主动散热和 5.1 V / 5 A 电源。

## 固定网络拓扑

- Raspberry Pi `eth0`：`10.99.0.2/24`。
- 开发机有线口：`10.99.0.1/24`。
- 两端有线接口均不设置默认网关和 DNS；该链路只用于 SSH、日志和部署。
- 有线 NetworkManager profile 的 DNS priority 保持默认 `0`，禁止负值；负值会排除 Wi-Fi DHCP DNS。
- Raspberry Pi Wi-Fi 单独配置 DHCP/默认路由和 DNS，负责互联网访问。
- 开发机 NetworkManager profile：`epuzzle-direct`，`ipv4.never-default=yes`。

这样有线直连不会抢占两台设备的 Wi-Fi 默认路由，也不依赖 DHCP 服务器。

## GPIO17 继电器上电安全

- Raspberry Pi 官方文档说明：上电复位时 GPIO 会先回到通用输入状态，之后才由固件和 Linux 配置。
- 当前继电器为低电平触发；安全关闭状态是 GPIO17 稳定输出 3.3 V 高电平。
- `/boot/firmware/config.txt` 固化 `gpio=17=op,dh,pu`，在固件阶段尽早将 BCM GPIO17（物理 Pin 11）设为输出高电平并启用内部上拉。
- 官方同时说明 `gpio=` 在上电后仍可能延迟数秒生效，因此继电器 `IN` 必须有外部硬件上拉到 3.3 V；软件不能消除最早期悬空窗口。
- Linux 启动后 `epuzzle-magnet-safe.service` 再次写高，`MagnetController.connect()` 请求 active-low line 时也以逻辑 `INACTIVE` 初始化。
- 负载使用 `COM–NO`；GPIO17 拉低时才允许继电器吸合。

## 服务划分

建议独立进程：

- camera
- vision
- supervisor
- robot_control
- act_policy（可选）

机械臂控制不得被 OpenCV 或 PyTorch 推理阻塞。通信可用本地队列/共享内存，图像只传最新帧引用。

## 启动自检

1. 检查电源和温度。
2. 检查五个舵机在线。
3. 检查相机分辨率与固定参数。
4. 检查标定文件、robot ID 和版本。
5. 检查 A4 标志点重投影误差。
6. 检查磁铁默认关闭。
7. 执行 HOME 小范围运动。
8. 通过后进入 WAIT_START。

## 性能优化顺序

1. 降低 ACT 输入裁剪尺寸，而不是降低全局视觉分辨率。
2. 减少相机数量。
3. 限制 CPU 线程，避免视觉和 PyTorch争抢全部核心。
4. 只在局部状态加载/运行 ACT。
5. 若仍不达标，关闭 ACT，不在比赛阶段临时迁移推理后端。

## 必备离线内容

- 固定版本 Python wheel/依赖缓存。
- LeRobot 配置和五轴插件。
- checkpoint 和数据 schema。
- 相机、桌面、机械臂标定。
- 一键启动配置。
- 不联网也能完成正式任务。
