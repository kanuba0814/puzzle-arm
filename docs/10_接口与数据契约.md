# 10 接口与数据契约

## 坐标系

- `image_px`：原始像素坐标。
- `rectified_px`：透视校正后的俯视像素。
- `table_mm`：A4 工作台毫米坐标，原点固定为纸张左下、x 向右、y 向上。
- `robot_base_mm`：机械臂基座坐标。
- `calibration_sheet_mm`：2026-07-31 触点纸左下角为原点、x 向右、y 向上、纸面 z=0；只用于该次标定证据。
- `joint_deg`：LeRobot 对外关节角，是否使用角度制由配置冻结。

所有接口必须写明坐标系和单位，不允许裸 `x/y/theta`。`calibration_sheet_mm` 不得静默冒充正式 `table_mm`；其到 `robot_base_mm` 的显式变换保存在 `workspace/calibration/contact_sheet_to_robot_base_20260731.json`。

## PieceObservation

见 `data_contracts/piece_observation.schema.json`。

必要字段：

- `piece_id`、`source_image_id`、`timestamp_ns` 和 `frame="table_mm"`
- `measured_contour`：只允许 `image_px|rectified_px`，表示实测物理轮廓
- `polygon_table_mm`：求解用虚拟几何，不冒充实测轮廓
- `center_table_mm`、`yaw_deg`、`equivalent_yaws_deg`
- `pick_point_table_mm`、`pick_clearance_mm`；footprint 未冻结时显式 `null`
- `confidence` 和 typed diagnostics；只有 `diagnostics.extra` 可自由扩展

## PlacementPlan

见 `data_contracts/placement_plan.schema.json`。

必要字段：

- source pose
- target pose
- order
- geometry/texture score
- plan confidence

**旋转基准约定（0° 基准）**：不测量碎片绝对朝向。`source.yaw_deg` 恒为
`0`（相机拍下的初始位置一律视为 0°），`target.yaw_deg` 即求解器相对旋转角
（拼图只需碎片间的相对方向）。机械臂运动学模型负责补偿自身 pan 变化；
调用方不得再次修改 yaw 或加入关节方向补丁。

**标准视角（2026-08-01 统一）**：所有水平面旋转角度一律以“俯视 A4 工作台”
为准——从上往下看，z 轴向上，磁铁磁吸面朝下、碎片贴附底面。在此视角下：

- 旋转角正值 = **俯视逆时针**（求解器 Δyaw 的 atan2 数学约定天然一致）；
- 本机实测硬件方向（2026-08-01）：`shoulder_pan` 物理角增大 = 俯视逆时针
  （与 FK 一致，位置标定验证）；`wrist_roll` 物理角增大 = 俯视**顺时针**
  （与 FK 假设相反，位置标定测不出朝向）；
- 工具俯视逆时针 yaw 统一由运动学模型表达为
  `yaw_robot = yaw_zero + pan_phys − wrist_roll_phys`；
- `tool_orientation.wrist_roll_yaw_sign=-1` 是标定契约的一部分；禁止继续使用
  `2*Δpan−Δyaw` 调用点补丁，也禁止退回未经方向验收的 `pan+roll` 公式；
- 任务空间 yaw 是周期量；J5 是单圈有界位置关节，两者的误差语义不得混用。

## MotionGoal

见 `data_contracts/motion_goal.schema.json`。

- `frame = robot_base_mm`；控制模块不接受 `table_mm` 或裸坐标。
- `position_mm`：机器人基座系 TCP 三维位置。
- `pitch_deg`：工具前向轴在机器人基座系内的俯仰角；点动和插值不得静默重置。
- `yaw_deg`：TCP 绕工具轴的目标朝向；按标定中的显式 wrist-roll yaw 符号解算。
- `phase`：HOME/SAFE/PREGRASP/PICK/PREPLACE/PLACE/RECOVERY。
- `speed_profile`：明确的速度档，不等同于已实测硬件速度。
- 可选 `path_constraint=LowHeightPoseLock` 只表示最后 30 mm 纯 Z 入口姿态保持：
  5 mm/段，yaw/pitch 各 ±5°，J5 需保留 15°限位余量；任务空间 yaw
  使用周期误差，有界 J5 关节误差使用普通绝对差。

## MotionResult

见 `data_contracts/motion_result.schema.json`。

- 包含 `success`、`error_code`、规划/执行路径点数、标定 ID 和最终五轴实际读回。
- 全路径必须在发送第一个舵机目标前完成 IK、软限位和步长预检。
- 目标寄存器写入成功不等于运动完成；成功结果必须由实际五轴位置连续稳定收敛确认。
- 失败结果不得触发电磁铁；电磁铁仍只能由 Supervisor 单独控制。

## ArmKinematicCalibration

见 `data_contracts/arm_kinematic_calibration.schema.json`。

- 仅适用于一台由原 SO-101 follower 改装的五轴机械臂。
- 显式保存几何 mm、五轴方向/零偏/软限位、工具 yaw 方向/零点、拟合与独立验收指标、证据 SHA256。
- `quality.status != accepted` 或指标超限时，真实控制构造必须失败。
- LeRobot 电机 calibration 与 TCP/运动学 calibration 是两类文件，缺一不可。

## CalibrationSheetToRobotTransform

见 `data_contracts/calibration_sheet_to_robot.schema.json`。

- 方向必须显式为 `calibration_sheet_mm -> robot_base_mm`，并同时保存可审计的反变换。
- 平移单位固定 `mm`，偏航单位固定 `degree`；禁止依赖字段名猜单位。
- 当前文件只用于 2026-07-31 触点纸证据；正式视觉链路仍需独立冻结 `table_mm -> robot_base_mm`。

## MotionGoal / MotionResult

见 `data_contracts/motion_goal.schema.json` 和 `data_contracts/motion_result.schema.json`。
`MotionGoal.timestamp_ns` 与可选 `deadline_ns` 必须同时来自 `time.monotonic_ns()`；
`deadline_ns` 是同一单调时钟域内的绝对截止时间，不是 Unix wall-clock。禁止由
`time.monotonic_ns()` 生成 deadline 后使用 `time.time_ns()` 比较。用于人类审计的墙钟时间
必须使用独立字段，不能复用运动 deadline。

## Robot observation/action

五轴固定顺序：

1. shoulder_pan.pos
2. shoulder_lift.pos
3. elbow_flex.pos
4. wrist_flex.pos
5. wrist_roll.pos

禁止根据字典遍历顺序隐式假设，数据导出时同时保存显式 feature names。

## MagnetCommand

见 `data_contracts/magnet_command.schema.json`。

Supervisor 是唯一允许调用 `MagnetController` 的全局状态模块。控制接口为：

```python
status = magnet_controller.set_enabled(enabled)
```

- `enabled=True`：请求继电器吸合、电磁铁通电；低电平触发，GPIO17 输出低电平。
- `enabled=False`：请求继电器释放、电磁铁断电；GPIO17 稳定输出 3.3 V 高电平。
- GPIO chip 固定为 `/dev/gpiochip0`，line offset/BCM 编号为 `17`；继电器控制链路已由操作者确认就绪。
- “控制链路就绪”不等于吸取、释放、电气或热验收通过，也不解除自动抓放门禁。
- 每次通电的软件工程上限为 `10000 ms`，到期自动断电；调用方不能覆盖。
- `close()`、急停和进程清理必须断电。GPIO 请求或写入失败不得返回成功。
- 线圈额定电压、电流、温升与实测连续通电能力仍为 `UNKNOWN`；10 秒不是硬件能力声明。

赛场 GUI 通过新增 CLI 命令 `manual-magnet-pulse` 和 `manual-magnet-off` 间接控制电磁铁；
GUI 进程不直接持有 GPIO line。CLI 单次运行有界，异常/超时/退出均尽力请求断电。

## Supervisor

见 `data_contracts/supervisor_config.schema.json` 和
`data_contracts/supervisor_result.schema.json`。Supervisor 是唯一可切换全局运行状态的
模块，并写入兼容 `runtime_event.schema.json` 的 JSONL。PARK↔HOME 是关节空间安全
过渡，必须逐步读回；普通笛卡尔动作仍只通过 `MotionController`。

抓放采用 fail-closed：PICK/PLACE 接触高度、正式 table-mm 变换、磁头净空、视觉和计划
时效、标定均有效前，禁止进入磁吸抓放状态，且不得调用磁铁吸合。shadow 模式禁止硬件
对象和动作。

## SupervisorRun 页面动作合同

赛场 7 英寸 GUI 的相机和机械臂动作都通过
`workspace/tools/supervisor_run.py` 短命子进程执行；GUI 自身不常驻串口或 GPIO。

```bash
supervisor_run.py <command> --status-file PATH --result-file PATH \
    [--piece-index N] [--target-angle DEG]
```

GUI 命令为 `detect`、`red-baseline`、`sweep-shortest`、`pregrasp`、`park`、
`puzzle-shadow`、`pick-place`、`commission-center`。CLI 同时兼容底层别名 `scan`、`sweep`、
`shadow-plan` 和 commissioning 用的 `repeat`。

新增命令：

- `competition-self-color`：自备纯色 50 分全流程；后端未接入前返回 `SUPERVISOR_LOCKED`。
- `competition-white`：现场白色 20 分全流程；通用视觉/正式抓放未冻结前返回 `SUPERVISOR_LOCKED`。
- `competition-card`：扑克牌 30 分全流程；texture/正式抓放未冻结前返回 `SUPERVISOR_LOCKED`。
- `manual-read-state`：五轴/TCP 实际读回；后端未接入前返回 `SUPERVISOR_LOCKED`。
- `manual-jog-joint`：单轴相对点动；后端未接入前返回 `SUPERVISOR_LOCKED`。
- `manual-jog-cartesian`：TCP 相对点动；后端未接入前返回 `SUPERVISOR_LOCKED`。
- `manual-magnet-pulse --duration-s S`：有界电磁铁脉冲，`S` 必须在 `(0, 10]` 秒内；
  使用 `MagnetController` 吸合并在 `S` 秒后释放。
- `manual-magnet-off`：立即释放电磁铁。

- 心跳文件见 `data_contracts/supervisor_run_status.schema.json`。
- 结果文件见 `data_contracts/supervisor_run_result.schema.json`；只有 `PASS` 且进程返回
  0 才算成功。stdout 仅进入诊断日志，不能作为 GUI 状态合同。
- shadow、检测和巡检的 `magnet_enabled` 必须为 `false`。
- `pick-place` 在 PICK/PLACE 接触高度和其他抓放门禁通过前必须拒绝。
- 失败时必须返回明确错误码；连接硬件后的异常路径必须尽力回正式 PARK，再断力矩。

## GUI 后端深接口

`workspace/src/integration/competition_backend.py` 提供赛场 GUI 唯一依赖的后端抽象：

```python
class CompetitionBackend(Protocol):
    def capabilities(self) -> Mapping[str, BackendCapability]: ...
    def build_request(
        self,
        command_id: str,
        parameters: Mapping[str, JsonValue],
        *,
        status_path: Path,
        result_path: Path,
    ) -> BackendRequest: ...
```

`BackendCapability` 字段见 `data_contracts/gui_backend_capability.schema.json`：

- `command_id`
- `availability`: `READY | LOCKED | UNAVAILABLE`
- `reason`
- `requires_robot`
- `requires_manual_unlock`

`SupervisorRunBackend` 实现把请求统一转换为 `supervisor_run.py` argv + timeout + status/result 路径；
GUI 只处理一种 `BackendRequest`。

## RobotMotionLock

见 `data_contracts/robot_motion_lock.schema.json`。真实硬件事件导致 PARK 或断力矩无法确认时，
创建 root 管理的 `/etc/epuzzle/robot-motion.lock.json`；仓库中的
`workspace/runtime/robot_motion_lock.json` 是同一事件的受 Schema 检查记录模板。**锁文件
存在即锁定**，即使设备节点后来重新出现也不得自动清除。GUI 必须禁用巡检、PREGRASP、
PARK 和普通断力矩按钮；CLI 必须在
构造硬件 adapter 前返回 `SUPERVISOR_LOCKED`。检测、Shadow 和急停仍可用。

解除锁必须由现场操作者完成文件中 `clear_requires` 的全部步骤并明确批准；程序不得自行
删除、改写为 unlocked 或因重启/USB 重枚举而忽略该文件。

## 时间戳

- 使用单调时钟保存内部时间；运动 `timestamp_ns`、`deadline_ns` 和 deadline 比较必须统一使用 `time.monotonic_ns()`。
- 相机帧、视觉结果、ACT 输出、舵机命令均带时间戳。
- 超过有效期的视觉目标和 ACT 动作必须丢弃。
