# 09 ACT 训练与树莓派推理

## ACT 角色

ACT 只学习局部抓取/放置技能。全局位姿由 OpenCV 和 IK 提供，避免 ACT 学习完整拼图的组合规划。

## 推荐策略形式

### 最低风险

输入：

- 顶置相机局部裁剪；
- 五个关节位置。

输出：

- 五个关节目标动作块。

启动状态由确定性控制固定在 PREGRASP/PREPLACE 附近，降低训练分布范围。

### 可选增强

把以下数值编码进 observation state：

- 目标相对误差 dx/dy/dz/dyaw；
- skill_id（GRASP 或 PLACE）；
- magnet_state。

这需要自定义 processor/feature 管线，首版不作为必需。

## 数据集拆分

不要把完整拼图录成一个长 episode。分为：

- `local_grasp`：从预抓取附近开始，到吸取后抬高结束。
- `local_place`：从预放置附近开始，到释放并抬高结束。
- `recovery`：单独记录失败恢复，不与普通成功示教混合。

## 数据覆盖

每个技能至少覆盖：

- 工作区不同位置；
- 不同碎片轮廓；
- 不同旋转角；
- 预抓取初始误差；
- 轻微照明变化；
- 不同已放置邻块状态。

建议节奏：

- 50-80 条做学习可行性验证；
- 150-250 条覆盖位置和角度；
- 根据实机失败定向补数据。

官方“约 50 条示教”只是部分简单任务的起点，不是本题成功率保证。

## 训练

- 在 RTX 2080 Ti 22.5GB 主机训练，Pi 5 不承担训练。
- 使用 LeRobot v0.6.0 ACT 默认配置作为起点。
- 先做短训练验证数据和维度，再增加训练步数。
- 验证集按完整 episode 和未见位置划分，禁止随机抽相邻视频帧造成数据泄漏。
- 每个 checkpoint 保存数据集版本、git commit、feature schema 和标定 ID。

## Pi 5 推理门槛

先以真实相机输入和最终 checkpoint 测量：

- 图像采集延迟；
- 预处理延迟；
- 单次推理 p50/p95；
- 动作发送周期；
- 内存峰值；
- CPU 温度与降频；
- 连续运行 30 分钟稳定性。

建议决策：

- p95 <= 300 ms：可进行局部动作测试。
- 300-500 ms：缩短接管范围、使用较长 action chunk，并严格验证开环风险。
- >500 ms 或出现积压：比赛版本禁用 ACT，回退到 IK。

这些是项目决策阈值，不是官方性能承诺。

## action chunk

- `chunk_size` 决定一次预测的未来步数。
- `n_action_steps` 决定实际执行多少步后重新推理。
- 不启用 temporal ensembling 时可一次执行多个动作。
- 启用 temporal ensembling 时官方配置要求 `n_action_steps = 1`，Pi 5 可能无法承担每步推理，首版不启用。

## 安全

ACT 输出先经过：关节限位、单步限制、速度限制、低高度限制和工作区限制。ACT 不能直接写电机总线。
