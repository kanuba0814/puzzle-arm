# 23 单臂运动控制重构

## 1. 实际拓扑

本项目只使用一台由原 SO-101 follower 改装的五轴机械臂：

1. `shoulder_pan.pos`（舵机 ID 1）
2. `shoulder_lift.pos`（舵机 ID 2）
3. `elbow_flex.pos`（舵机 ID 3）
4. `wrist_flex.pos`（舵机 ID 4）
5. `wrist_roll.pos`（舵机 ID 5）

不存在 leader/follower 双臂运行关系，也不存在 ID 6 `gripper.pos`。电磁铁不是机械臂关节，由 Supervisor 通过 GPIO17 的 `MagnetController` 独立控制。

`docs/14_三人分工与交接.md` 仅为已废弃的历史分工草案，不作为架构、接口或验收依据。

## 2. 重构 seam

控制模块的外部 seam 保持为：

```text
MotionGoal(robot_base_mm) -> MotionResult
```

调用方不接触 IK 分支、舵机字典顺序、轨迹采样、收敛轮询或标定文件内部字段。控制模块内部使用两个 seam：

- `KinematicModel`：显式五轴关节向量与 `robot_base_mm` TCP 位姿互换；
- `JointRobot` adapter：读取五轴状态、发送五轴目标，不控制电磁铁。

## 3. 首阶段验收条件

### A. 数据与标定

- 五轴字段必须精确匹配固定顺序；出现 `gripper.pos`、缺字段或额外字段立即拒绝。
- 运动学参数只能从版本化 JSON 标定文件加载；禁止源码内加入单点补偿或未注明来源的魔数。
- 标定文件必须记录机械臂来源为 `so101_follower_modified_single_arm`、坐标系、单位、样本 SHA256 和质量状态。
- 未达到 `accepted` 状态时，真实硬件 adapter 必须拒绝动作。
- 标定至少保留 4 个未参与拟合的独立触点；内部工程门槛为：XY RMS 不大于 5 mm、XY 最大误差不大于 8 mm、Z 最大绝对误差不大于 3 mm。

### B. 规划

- 收到目标后先生成并验证全部路径点；任一点 IK 不可达、关节超限或数值非法时，在发送第一个舵机目标前整体拒绝。
- `pitch_deg` 表示机器人基座系内工具前向轴俯仰；`yaw_deg` 表示腕滚转目标。不得在点动时静默重置姿态。
- 轨迹采样间距、关节步长和软限位必须由显式配置给出。

### C. 执行

- 每个路径点发送后必须读取实际五轴位置并达到显式容差；连续稳定样本不足或超时返回失败。
- 目标写入成功不等于运动完成；不得只检查 `Moving` 位或目标寄存器。
- `MotionResult` 必须包含错误码、规划/执行点数、最终五轴读数和时间戳。
- `MotionGoal.timestamp_ns`、`deadline_ns` 及控制器 deadline 比较必须统一使用 `time.monotonic_ns()`；禁止与 `time.time_ns()` 墙钟混用。
- 中间路点必须按显式 `waypoint_min_dwell_s_by_profile` 节流；不能因一次仍未移动的读回恰好落在宽跟随容差内，就在毫秒级连续发送全部路点。终点仍使用正式容差。
- `Goal_Velocity` 是舵机速度配置，应在 profile 改变时写一次；不得每个位置路点重复写入。位置动作继续使用官方 `FeetechMotorsBus` 的 `sync_write("Goal_Position")`。
- 控制模块不得吸合或释放电磁铁；只有 Supervisor 可以在成功的运动结果之后调用电磁铁。

### D. 安全上线

- 本阶段不自动下发真实舵机位置。
- 新控制核心先以离线测试和 FakeRobot 验证，再部署到树莓派的非激活路径。
- 完成新的五轴 LeRobot 标定、TCP 测量和独立触点验收后，才允许切换真实 adapter。

## 4. 2026-07-31 accepted 基线

- 五轴电机标定已从用户确认的同一台 follower 历史包精确提取 J1–J5，并经舵机寄存器回读一致性验证；拒绝 J6。
- TCP 轴向长度单次卡尺实测为 `40.17 mm`；结合腕部结构初值，模型使用 `tool_forward=101.27 mm`、`tool_normal=18.1 mm`。
- 只使用 A/B/D/E/F/G/H/I 八个 fit 点拟合；M/N/O/P 四点不参与拟合、模型选择或软限位生成。
- holdout 结果：XY RMS `2.480912 mm`、XY max `3.406456 mm`、|Z|max `2.458668 mm`，通过内部 5/8/3 mm 门槛。
- 用户明确决定直接接受该结果；accepted 文件为 `workspace/calibration/arm_kinematics_single_arm_accepted_20260731.json`。
- 保留风险：手绘点位误差未定量、TCP 仅单次测量、历史 URDF 原件哈希未知、软限位尚非完整自碰包络。接受状态不等于允许立即执行低位或带磁铁动作。

## 5. 首次硬件往返

- 为满足竞赛节奏，soft limits 使用同机机械端点内缩后的实用范围，不再使用触点包络：J1 ±110°、J2 ±100°、J3 ±90°、J4 ±95°、J5 `[-145,-20]°`。
- 首次使能先在断力矩状态把五轴目标对齐实际读数；2 秒保持期间编码器漂移为 0。
- 高位无磁铁往返 `park → HOME → P → Q → P → HOME → park` 通过，最大跟随误差 `4.341246°`，阶段最终最大误差 `2.637363°`。
- production `MotionController` 的 P/Q 高位路径随后全部成功，规划/执行 waypoint 数一致并由实际五轴读回确认。
- P 点 10 mm 目标经操作者观察为过低或碰纸，不得作为自动 clearance；20 mm 单独停留 10 秒后确认合适，冻结为 PREGRASP/观察高度。PICK 接触高度仍为 `UNKNOWN`。
- 快速巡航允许较宽的中间 waypoint 门槛，但精确终点必须另行保持。D 点实测冻结竞赛终点补偿：沿目标到机械臂反方向 3 mm、命令 pitch `-87.5°`；负载后实际 pitch `-90.03°`，重复两次由操作者确认位置和垂直度正常。
- 结束已返回原停放位并断力矩；吸取和 Supervisor 仍未执行。

## 6. USB 恢复后的正式巡检

- 现场操作者重启 Pi、恢复舵机供电并手动删除事故锁后，只读确认五轴设备与校准寄存器一致。
- PARK 过渡增加最终实际位置验收：途中 8° 跟随门槛不能替代正式 PARK 4° 终点门槛。
- 首次恢复巡检因 Supervisor 的 monotonic deadline 被 `MotionController` 默认 wall-clock 错误比较而 fail-closed；route 为空、磁铁关闭、异常清理后仍在 PARK 且断力矩。
- 统一 deadline 时钟域并通过回归后，磁铁关闭的最短巡检通过：`red-1 -> red-2 -> red-0 -> red-3`，四个中心均有实际五轴读回，最终 PARK 最大误差 `3.516483°`，五轴 Torque_Enable 全 0。
- 证据位于 `workspace/calibration/evidence/2026-07-31_usb_recovery_and_sweep/`。该结果只验收空载磁铁关闭巡检，不解除 PICK/PLACE、磁吸能力或通用视觉 Gate C 门禁。
